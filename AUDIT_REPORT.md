# CompleteQuranVocabulary audit

Audit date: 2026-11-06, America/New_York. Scope: the supplied repository, its current inputs and generated artifacts, and the retained isolated diagnostics. Notebook cell numbers below are **zero-based**, including Markdown cells. No production code or data was corrected during this audit.

## 1. Executive verdict

**FAIL as a deck a learner can presently trust without checking individual cards. FAIL for public-release readiness. PASS WITH CAVEAT for reproducible offline computation from the supplied snapshots.**

The pipeline is structurally much stronger than its lexical decisions. It reproducibly processes 128,219 QAC segments into 77,885 included occurrences and 4,875 vocabulary identities. Selected references, lexical segments, context targets, and location tags align internally. The existing 100-card package is structurally valid, and a diagnostic 4,875-card package imports without duplicates while retaining review scheduling.

Those successes do not establish that a card teaches the right word. Confirmed examples include a bookseller headword for “my letter,” a summit headword for “obedient,” the headword “child” for “parents,” an active participle for a passive one, and “creation” as the definition of “creator.” Many have Auto QA=False. Human review is also compromised: current overrides include malformed Arabic and a literal `:skip` plural. A routine upstream rebuild erases those reviews entirely.

The principal release blockers are:

1. Wrong lexical identities, headwords, plurals, and definitions passing the current checks.
2. Destructive regeneration and unversioned human approvals.
3. Unverified audible identity across the deck, despite valid media formats and synchronized fallback fields.
4. Missing redistribution authorization/notices and unresolved source-license scope.
5. Incomplete deliverable: the production package contains only 100 cards, and the final CSV is behind ten manual reviews.

These are systemic failure modes, not a list of isolated spelling corrections. Correcting only the examples in this report would not establish readiness. No error-rate estimate is justified by the purposive sampling.

Actual dataflow:

```text
QAC morphology → parsed segments → lemma-bearing stems + selected PRON/DEM/REL stems
                                ↘ QF coordinate join → merged occurrences
merged occurrences + full QAC structure → frequency, tiers, cleaned gloss evidence
QuranMorph + Kaikki + CAMeL → frozen vocabulary/evidence and occurrences
frozen tables + manual CSV → headword, definition, plural, QA
Tanzil + QF English → orthographic context map → representative occurrence
all occurrence locations → tags → final CSV
selected rows → audio resolution → HTML fields → genanki package
```

QAC `LEM:` strings, including numerical discriminators, become `Vocabulary ID`. Pronouns without lemmas use `POS:ArabicBuckwalter`. These are source-dependent identities, not externally guaranteed permanent lexeme identifiers. All prefixes and suffixes are excluded as vocabulary entries; 30 excluded stems are INL. Some grammatically attached pronouns are nevertheless QAC STEM rows and enter the deck.

Offline replay reconstructed the merged table exactly and matched every frozen-table column using serialized-value comparisons. CAMeL evidence was reproduced too. Notebook 04 ran in a fresh Python namespace, without notebook output/state, with pip magic omitted and package network downloads excluded. Repetition produced a byte-identical final CSV. This is strong snapshot reproducibility, not proof of reproducible future API ingestion or portable environment installation.

## 4. Confirmed defects

The following findings are reproducible from the supplied inputs and retained diagnostics. Proposed fixes are recommendations only.

### D01 — Critical: rebuilding destroys manual review

**Location:** 03 c37, manual queue initialization and `manual_review.to_csv`. **Evidence:** isolated full execution resets all 278 entries to Reviewed=False and blank overrides; production currently contains 188 reviewed entries. `replay03.log` records `RESET REVIEW {False: 278}`. **Fix:** separate queue generation from decisions; merge new IDs into existing decisions, reject overwrite, keep backups/version history. **Regeneration/re-review:** engineering fix need not alter cards; lost decisions require restoration or re-review. Never run this cell against the working manual file first.

### D02 — High: dictionary matching selects different words

**Location:** 03 c17,21,23,25,27; 04 c6–7. **Evidence:** `qaAnit` selects قُنَّة through the dictionary's dual قُنَّتَيْن, not قَانِت; `kita`biY` selects كُتُبِيّ, whose retained dictionary sense is “bookseller,” for the occurrence “my letter”; `wa`liday` selects وَلَد for parents. `Hunayon` selects حَنِين for حُنَيْن. These are traceable to candidate entries in `linguistic_samples.log`, not conjecture based only on spelling. “Strict” still removes vowels and shadda and matches inflections. **Fix:** preserve vocalized/form evidence; distinguish headword from inflection matches; validate derivational form, root, grammatical role and sense before promotion. **Regeneration/re-review:** yes; review the whole candidate-selection population, not just relaxed matches.

### D03 — High: automatic headword precedence violates morphology

**Location:** 04 c7 `choose_headword`; 03 c23 QuranMorph queries. **Evidence:** `yasotaEotibu` → عَتَبَ although the occurrence is form X; `>aTohar` → طَاهِر loses the comparative; `mula`qiy` → مُلْقًى changes participial identity; `muxal~afuwn` → مُخَلِّفٌ and `m~ugoraquwn` → مُغْرِقٌ invert passive/active vocalization. Current replay directly uses QuranMorph for 2,575 headwords. Some wrong outputs arrive indirectly through Wiktionary and therefore carry a reassuring dictionary source label. **Fix:** require morphology-compatible evidence, especially voice and derived verb form; use uncertainty rather than automatic promotion when sources conflict. **Regeneration/re-review:** yes, including reviewed rows whose automatic fields remain live.

### D04 — High: plurals belong to other candidate lexemes

**Location:** 04 c11–12 `extract_plural_candidates`, `choose_plural`. **Evidence:** غَلْيٌ receives أَغْلَال from a shackle candidate; خِزْيٌ receives خُزُوز from a silk candidate; خَالِقٌ receives أَخْلَاق / خِلَق / خُلْقَان. The chosen headword can come from QuranMorph while plural extraction still uses unrelated Wiktionary candidates. **Fix:** derive morphology only from the accepted dictionary identity; distinguish attested Qur'anic plurals from supplementary dictionary plurals. **Regeneration/re-review:** yes, all automatic plurals need targeted validation.

### D05 — High: fuzzy English agreement is not semantic agreement

**Location:** 04 c9–10, `fuzzy_token_match`, `definition_support`, `choose_definition`; 03 c12 evidence restriction. **Evidence:** “creation” versus “Creator” scores 0.97 with precision 1.0, and the actual خَالِق card teaches “creation.” Fault test “to lie” versus “to live” scores approximately 0.988. `labiva` has only one cleanest-tier gloss, “and not he delayed,” despite 30 occurrences. `walada` teaches “he was born; Allah has begotten,” promoting contextual wording into an isolated lexical definition. **Fix:** use lexical/syntactic sense verification; preserve negation, voice and argument distinctions; inspect evidence beyond the cleanest tier; do not treat string similarity as confidence. **Regeneration/re-review:** yes, including the 819 dictionary-plus-QF definitions and QF fallback definitions.

### D06 — High: manual data contains malformed learner-facing content

**Location:** `manual_lexeme_review.csv`, identified by Vocabulary ID; 04 c7,10,12. **Evidence:** 20 current reviewed headwords have doubled terminal base letters, including `m~u&oSadap` مُؤْصَدد, `muta$a`kisuwn` مُتَشَاكِسس and `m~usotaTar` مُسْتَطَرر. `rijoz` has Manual Plural=`:skip`; `s~aAhirap` has سَاهِرَةة and Arabic contamination inside the English definition. These propagate with QA=False. The count is a reproducible anomaly count, not a complete count of manual linguistic errors. **Fix:** restore/edit against original evidence, validate field types and commands, preview Arabic after saving, re-review all 188 accepted rows. Investigate input corruption without assuming its cause. **Regeneration/re-review:** yes.

### D07 — High: Auto QA grants false assurance and approvals never expire

**Location:** 04 c13 `needs_review`; `qa_review.py` review queue/save logic. **Evidence:** reviewed rows return False even for injected empty headword/definition. Many D02–D05 examples are unflagged. Current nonmissing definition scores have minimum about 0.637; the `<0.15` test cannot catch accepted scores under the current selection thresholds. A review flag is not tied to the automatic content reviewed. Blank overrides mean future automatic changes are silently accepted too. **Fix:** retain unconditional integrity checks; separate review-needed reasons; store content/source hashes and invalidate approvals when relevant content changes. **Regeneration/re-review:** regenerate flags and review affected content; broad re-review necessary for current semantic failures.

### D08 — High: inclusion and identity differ from the stated pronoun policy

**Location:** 01 c6 `is_vocabulary_entry`, `get_vocabulary_id`. **Evidence:** QAC STEM includes the pronoun in لَكِ at 3:37:21 and بِهِمُ at 34:9. There are 2,461 prefixed PRON occurrences; raw Buckwalter variants create separate IDs such as `PRON:humo`, `PRON:hum`, `PRON:humu`. Downstream `PRON:ki` becomes لِ and `PRON:himu` becomes بِ. **Fix:** decide explicitly how bound/independent pronouns and recitational variants should be represented; introduce a reviewed identity map without erasing real homographs. **Regeneration/re-review:** yes; changed identity requires GUID migration, frequency recomputation and duplicate retirement.

### D09 — Medium: QuranMorph “word” is not always authentic display text

**Location:** `quran-morph.csv`, `word`; 04 c1/ranking. **Evidence:** 208 coordinates append literal نَن relative to QAC and Tanzil, e.g. رَبِّنَن at 2:126:4. Three selected final `Quranic Form` fields contain this suffix (`laday`, `wa`liday`, `nakiyr`). Current package HTML uses the correct Tanzil target, limiting visible damage; ranking and exported provenance still consume the faulty string. **Fix:** verify and quarantine these input tokens; choose a validated orthographic display source. **Regeneration/re-review:** rebuild occurrence selections and re-review changed examples. Do not assert that the suffix's upstream origin is known.

### D10 — Medium: valid English `None` is parsed as missing

**Location:** 03 c1 default `pd.read_csv`, then gloss aggregation. **Evidence:** five literal negative-word translations at 14:9:14, 16:79:9, 18:22:19, 18:27:8 and 56:79:1 become NaN with default pandas parsing. In 04 `keep_default_na=False` correctly preserves them, e.g. “None / can change / His Words.” **Fix:** explicit missing-value policy for text columns. **Regeneration/re-review:** regenerate evidence; inspect changed definitions. This is not a defect in displaying the English word “None.”

### D11 — Medium: waqf parsing alters displayed text

**Location:** 04 c4 `split_tanzil_ayah`. **Evidence:** strips all no-stop, paired-stop, sakt, rub and sajdah signs. Input counts are 68, 12, 7, 199 and 15 respectively. Only accepted ending marks are restored. Thus “unchanged Tanzil text” is inaccurate. **Fix:** retain original display tokens/signs separately from coordinate/boundary indexing; preserve nonboundary annotations. Clarify licensing treatment of excerpts/formatting. **Regeneration/re-review:** regenerate contexts and inspect recitation edge cases.

### D12 — High: successful HTTP response is treated as valid audio

**Location:** 04 c23 `download_audio`. **Evidence:** mock HTTP-success HTML is written and returned as `.mp3`; existing cache is accepted without validation; write is not atomic. Current packaged files did parse as MP3, so this is a proven failure path, not a claim that current media are HTML. **Fix:** validate type, signature, decode/duration and completeness; atomic cache writes; explicit failure manifest and build policy. **Regeneration/re-review:** revalidate media; replace failed assets and verify any changed occurrence.

### D13 — Medium: fallback search discards usable alternatives

**Location:** 04 c15 hard filters; c26 `resolve_audio_for_card`. **Evidence:** `samaA^'` has 310 occurrences but its ranked result contains one; injected failure tries only that one. `kaAna` retains 323 of 1,358 occurrences. **Fix:** preserve a complete preference ordering or progressively relax filters for fallback. **Regeneration/re-review:** rebuild affected media/cards and verify context; no lexeme re-review unless example meaning changes.

### D14 — Medium: frequency changes do not update study order

**Location:** 04 c26 `genanki.Note` omits `due`; model defaults to sort field 0. **Evidence:** all new cards have due=0. Initial sampled Anki queue follows insertion rank, but an update experiment with changed ranks queues `{ll~ah` rank9999 before `maA` rank1. **Fix:** encode new-card position and document/apply an explicit repositioning strategy that preserves learning/review scheduling. **Regeneration/re-review:** package/scheduling migration; no linguistic re-review.

### D15 — Medium: current outputs are stale and incomplete

**Location:** final CSV, test package, 04 c27. **Evidence:** current manual file has 188 reviews versus 178 applied to saved CSV; fresh run changes ten IDs, six headwords and nine definitions. Production APKG has only 100 notes/cards; full output path is declared but never built by the active call. **Fix:** build a versioned full release only after corrections, with manifest linking manual/input/package hashes. **Regeneration/re-review:** yes; especially because some newly applied manual entries are themselves malformed.

### D16 — High: credential embedded in source

**Location:** 01 c1 `CLIENT_SECRET` and client configuration. **Evidence:** plaintext assignment; value intentionally omitted here and not used by the audit. Exposure outside this workspace and current validity are unknown. **Fix:** rotate if potentially exposed, remove from shareable source/outputs, load securely from environment. **Regeneration/re-review:** no card changes needed.

### D17 — High: redistribution requirements are not satisfied or established

**Location:** package deck description/templates and project notice/provenance inventory. **Evidence:** deck description empty; only visible source credit is “Pause segmentation: Tanzil.net”; no full source notice/license bundle or recorded redistribution grants. Section 9 details the external basis. **Fix:** obtain applicable permissions, preserve required notices and page-level attribution, define component license boundaries before distribution. **Regeneration/re-review:** at least repackage; changing sources requires full affected-data review.

### D18 — Low: initial-shadda normalization is defeated by Unicode ordering

**Location:** 04 c14 `vocalized_compare_key`. **Evidence:** after NFC, initial vowel precedes shadda; `text[1] == shadda` fails. Test keys for مُّقَرَّب and مُقَرَّب remain different. **Fix:** inspect combining marks belonging to the first base letter, not a fixed character offset. **Regeneration/re-review:** rerank and inspect changed examples/audio; definitions need not change.

## 5. Unverified assumptions

- **Audible identity:** no listening-based certification of all selected recordings. Forty-four valid sampled responses and 100 decoded packaged MP3s prove format/availability, not the spoken word.
- **Source licenses at acquisition:** present web terms do not establish the historical grant under which local snapshots were obtained. No private permission letters were available.
- **Cross-platform presentation:** Anki backend tests do not certify Android/iOS fonts, clipping, night mode, screen readers or playback.
- **Complete linguistic accuracy:** neither the 365-row sample export nor matching coverage measures certify the remaining cards. Expert Classical Arabic review remains required.
- **Future source identity stability:** QAC lemma spelling/discriminator changes may split or merge GUID identities.
- **General clean-install reproducibility:** cached snapshots and the installed environment worked; authentication, current endpoints, CAMeL resource installation and unpinned dependency installation were not rebuilt from scratch.
- **Package-wide media completion:** the full diagnostic package intentionally omitted audio; full-deck CDN availability is not established.

## 6. Missing checks / overlooked risks

Important checks absent from the production pipeline include headword-to-root/form/voice validation; candidate-level plural linkage; pronunciation confirmation; manual-input anomaly checks; review-content versioning; and actual package import regression tests.

Further risks requiring explicit policy:

- A count-preserving permutation or wrong same-length source token passes current alignment assertions. The 208 QuranMorph anomalies demonstrate why coordinate joins need textual checks.
- `missing_quranic_words` counts empty strings after `astype(str)` but does not catch NaN converted to `'nan'`. QF context deduplication occurs before uniqueness assertion, masking duplicate conflicting rows. Current snapshots passed stronger audit checks; these are latent guards, not demonstrated present join failures.
- English cleanup cannot reliably allocate whole-word meanings across multiple lexical segments. There are 486 multi-vocabulary orthographic words. Prefix/suffix removal is a limited regex heuristic; the remaining phrase can still contain material contributed by other segments or nearby words.
- Blank manual plural means “use automatic,” so the review schema cannot explicitly suppress an incorrect automatic plural. `:clear` removes an override, not the resulting automatic content.
- Both review tools replace CSV atomically, but neither provides concurrent-edit reconciliation/version checks. Atomic replacement does not prevent lost updates between two reviewers.
- Pickles are trusted-code serialization, not a safe interchange format for arbitrary downloaded replacements.
- Network fallback makes realized package content depend on transient availability. The CSV is exported before fallback, and the builder does not save a realized occurrence/media manifest.
- Same filename is tied to occurrence identity, not audio content hash. A changed CDN recording at the same URL lacks a documented cache/update policy.
- Normalization, dependency versions and source changes can alter tied ranks/candidates. Existing deterministic output does not establish determinism across environments.
- No supported rule exists for retiring old GUIDs after lexical merges/splits. Reimport does not automatically remove obsolete notes.

## 7. Linguistic and data-quality risks

The strongest semantic evidence is the mismatch between intended lexeme and retained candidate meaning. For `qaAnit`, the source candidate actually says summit; for `kita`biY`, bookseller; for `mula`qiy`, a passive participle of أَلْقَى. These errors are not debatable choices between plausible English synonyms.

The form-X analysis of 41:24:7 is independently described by [QAC morphology](https://corpus.quran.com/wordmorphology.jsp?location=(41:24:7)). Its mapping to form-I عَتَبَ is therefore indefensible as citation normalization. [QAC 27:28:2](https://corpus.quran.com/wordmorphology.jsp?location=(27:28:2)) identifies the noun in “with my letter”; the bookseller mapping cannot be justified by that occurrence. [QAC 3:37](https://corpus.quran.com/wordbyword.jsp?chapter=3&verse=37) explicitly distinguishes the prefixed preposition and feminine pronoun in لَكِ.

Additional risks found across strata:

- **Weak/derived verbs:** normalization may erase a derived form rather than recover its perfect citation form. Examples include قَٰتَلَ mapped to قَتَلَ and أَرَيْ mapped to رَأَى. Some imperfect citation remnants remain, such as تَصِيرُ.
- **Proper names:** broad PN→name/noun matching allows a common noun with the same unvocalized spelling; حُنَيْن and عِمْرَان are examples.
- **Participles:** occurrence metadata is consistent, but final display omits participle type and can contradict it. Gender normalization also needs a declared policy; a masculine citation headword with a female-specific gloss can confuse learners.
- **Plurals/duals/collectives:** singularizing all nouns is not always pedagogically or lexicographically appropriate. Dictionary plural count is not evidence of a Qur'anic plural. Do not repair this with suffix stripping.
- **Function words:** a short list of common translations is not a grammatical account. إِن, مَا, قَد and demonstratives need contextual/function distinctions, not merely frequency-ranked gloss strings.
- **Homographs and duplicate fronts:** 563 rows share a headword; 498 share headword/plural fronts. Some are legitimate distinct senses; others reflect failed canonicalization or fragmented source identity. Fifteen numerical discriminators are preserved structurally, but the lookup ignores their semantics.
- **Definition register:** 3,868 current definitions use QF fallback; 1,109 contain brackets/parentheses. Many retain person, tense, articles or verse-specific clauses. These are useful evidence but not automatically suitable dictionary definitions.

The sample includes 50 top-frequency rows; 20 each of rare, verb, noun, participle, proper-name and QA strata; all 125 function-word rows selected by the diagnostic, all 63 relaxed-match rows, 25 manual rows, 15 numbered homographs and 23 regression entries, with overlap: **365 unique rows**. Exported inclusion is not independent certification of every translation. Good-looking samples such as honey, spun yarn and cooking pots do not offset systematic failure mechanisms.

Frequency totals are correct for the selected segment population. Thresholds are 64/332/471/694/1,102/1,997 IDs for 50/75/80/85/90/95% respectively. They must not be advertised as percentages of Qur'anic comprehension or all grammatical tokens.

## 8. Anki/package/rebuild risks

**Verified:** deck ID 2059400110, model ID 1607392319, GUID based on namespace plus raw Vocabulary ID. All package GUIDs matched the formula; existing media references resolved; SQLite integrity was OK. Actual Anki 26.9.4 backend imports into a disposable collection yielded 100 → 4,875 → 4,875 notes/cards. Existing note/card identity and a deliberately set review interval, due date and repetition count survived updates.

**Update limitation:** tests used explicit import options. “Always update” overwrote local fields and tags; “if newer” retained a deliberately newer local edit. A future correction is not guaranteed to replace a user's newer edit. These are Anki update semantics, not evidence of duplicate generation. Official [packaged-deck documentation](https://docs.ankiweb.net/importing/packaged-decks.html) also warns about note-type changes and describes update options.

The 16 fields are, in order: VocabularyID, Headword, Plural, Definition, Root, POS, Frequency, FrequencyRank, QuranicForm, OccurrenceGloss, ExampleReference, Audio, ObservedForms, HeadwordSource, DefinitionSource, NeedsReview. Preserve this contract or test a migration. `QuranicForm` actually stores highlighted context HTML; `OccurrenceGloss` actually stores the full context English. Their names no longer accurately describe their values. Neither exact word coordinate nor lexical segment nor realized fallback provenance is packaged in a dedicated field.

The front has Arabic headword/plural and one recognition card. Text is escaped; the Arabic container uses RTL and bidi isolation. Font families are requested but not bundled. There is no demonstrated browser/mobile render QA. Slash-separated English should be explicitly labeled word-by-word support, and audio should be labeled as the highlighted orthographic word rather than a pronunciation of the canonical headword or the whole phrase.

Successful fallback synchronization passed injected testing, but only within surviving ranked candidates. No fallback was detected in the existing 100-note package. Media names are deterministic SHA-1 prefixes of vocabulary ID/reference/path; no collision was observed. The builder tolerates missing audio and does not produce a persistent failure report. Full package validation therefore remains unfinished as a product requirement, although its absence has been audited.

## 12. Personal-use readiness vs public-release readiness

**Personal use: FAIL as an unattended memorization source.** A careful learner can use the project as an evidence browser, checking each card against Arabic morphology and context. Merely excluding NeedsReview cards is insufficient: numerous confirmed errors are unflagged. A small independently reviewed subset could become usable sooner than the whole deck. Existing-source storage/permission questions should still be resolved; personal use is not a blanket legal exemption.

**Public release: FAIL.** Require corrected semantic selection, re-reviewed manual content, demonstrated audio identity, complete validated package, import/migration guidance, and documented redistribution rights/notices. The current 100-card package should not be presented as the complete lexicon.

**What is sound:** offline transformations are reproducible from supplied snapshots; inclusion counts and ranks are internally consistent; joins and selected occurrence coordinates hold; broad text alignment is largely supported after explicit orthographic reconciliation; tag aggregation matches the selected corpus; fallback field synchronization works in the tested branch; stable GUIDs and scheduling preservation work in tested Anki imports. These are substantial foundations, but they do not compensate for teaching the wrong word.
